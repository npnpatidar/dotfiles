## 1. Overview

This is a **NixOS + home-manager flake-based dotfiles repository** that manages two hosts:

| Host        | Platform         | Role                                                                 |
|-------------|------------------|----------------------------------------------------------------------|
| **alma**    | aarch64-linux    | Cloud/VPS server — runs all public-facing services (nginx, mail, SSO, DNS, etc.) |
| **aspire7** | x86_64-linux     | Laptop/workstation — daily driver with Niri WM, AI tooling, gaming, media |

The repo uses:
- **flake-parts** for modular NixOS/home-manager module architecture
- **sops-nix** for secret management (YAML-based encrypted secrets)
- **quadlet-nix** for declarative Podman containers
- **pre-commit-hooks.nix** + **treefmt-nix** for code quality
- **import-tree** to auto-import all `.nix` files in `./modules/`
- **lanzaboote** for Secure Boot on aspire7
- **herdr** as the terminal workspace manager for AI coding agents (replaced zellij)
- **lazyvim-nix** for the Neovim LazyVim distribution

### Outputs Structure

Uses `flake-parts` with `import-tree` to auto-load all modules under `./modules/`. Each `.nix` file in the modules tree exports a `flake.*` attribute that gets merged.

Modules follow a naming convention:
- `flake.nixosModules.*` — NixOS system modules
- `flake.homeModules.*` — home-manager modules
- `flake.modules.generic.*` — generic/shared constants
- `flake.wallpapers.*` — wallpaper references

Some modules also export `perSystem.packages.*` for CI pre-building/caching (see §16).

#### NVIDIA

#### Acer Battery (`acer-battery.nix`)
- Out-of-tree **acer-wmi-battery** kernel module built against the running kernel
- `enable_health_mode=1` modprobe option; health mode caps charge at ~80%
- `acer-battery-health-toggle.service` (oneshot, toggles `/sys/bus/wmi/drivers/acer-wmi-battery/health_mode`)
- `acer-battery-toggle` CLI script with Noctalia notifications (sudo NOPASSWD for the service only)
- Bound to `Mod+Shift+B` in Niri

#### Power Management (aspire7 only)
- **Tools:** auto-cpufreq, thermald, upower, powertop
- **Trigger:** battery **level < 75%** (was: AC plugged in) — above 75% the system runs at full performance
- **`power-supply-handler.service`:** Custom systemd service that:
  - **≥75% battery:** Enables all CPU cores, starts Immich/Filen services, sets performance governor (`auto-cpufreq --force performance --turbo auto`), enables peripherals (webcam, speakers), sets GPU to 1300 MHz
  - **<75% battery:** Disables half CPU cores, stops services, sets powersave governor + turbo never, blackens kitty background, removes secondary NVMe, sets GPU to 800 MHz, sets display to 60 Hz
- **Udev rules:** Trigger on charging/discharging state change
- **`power-supply-handler.timer`:** Re-evaluates every 5 min (3 min after boot) so the 75% threshold is honored between state changes
- **Sysctl tuning:** dirty page ratios, NMI watchdog off, swappiness

#### Bluetooth
- Dual controller mode (dual = BR/EDR + LE)
- Auto-enable, fast-connectable
- Auto-connect for input HID devices on boot

- **DNS:** explicit upstreams (Quad9 DoH + 8.8.8.8 + 1.1.1.1, load_balance), DNSSEC on, safe browsing + parental enabled
- **Blocked services:** social media (Facebook, TikTok, Discord, Snapchat), Gaming (Steam, Epic, Blizzard, Roblox), Streaming (Netflix, Disney+, Hulu, Spotify, Twitch), Shopping (Temu, Shein, Aliexpress), Dating apps, Messaging (WhatsApp blocked via Facebook), etc.

- **Clients:** Tailscale IPs 100.64.0.1-4

#### 5.4.3 Pocket ID + Tinyauth (alma)

- **Tinyauth:** OAuth2 proxy middleware (nginx auth_request)

## 16. Key Design Decisions & Patterns

### Module Pattern
Every `.nix` file under `modules/` exports one or more `flake.*` attributes:
```nix
_: {
  flake.nixosModules.moduleName = { ... }: { /* NixOS config */ };
  flake.homeModules.moduleName = { ... }: { /* home-manager config */ };
}
```
This allows `import-tree` to auto-discover and merge them into the flake outputs.

### Secret Adoption Pattern (sops-nix)
Secrets are stored in sops-nix YAML files and decrypted at build time:
```nix
sops.secrets.my_secret = {
  sopsFile = ../../secrets/shared.yaml;
  neededForUsers = true; # optional
};
```
Then referenced via `config.sops.secrets.my_secret.path`. Secrets shared by all hosts live in `shared.yaml` (e.g. `llama_cpp_api_key`, `gh_token`).

### sops Template Pattern
`sops.templates` renders decrypted secrets into files at activation (e.g. `~/.config/gh/hosts.yml` from `gh_token`) — keeps secrets out of the Nix store without a manual activation script.

### OIDC Seed Pattern
`pocket-id-seed.service` provisions OIDC clients, verifies stored secrets against the token endpoint, and rotates stale ones. Downstream services (`gitea-oidc-setup.service`) run `before` the app starts so in-memory provider registrations never hold stale secrets.

### Host Specialisation
Host-specific modules (alma vs aspire7) provide:
- Hardware config + packages
- Host-specific service config (syncthing, networking, etc.)
- Host-specific home-module additions

### perSystem Cache Pattern
Modules export `perSystem.packages.<name>` building the **exact same derivation** the host uses (`pkgs.path` with mirrored `nixpkgs.config`), so CI can pre-build and push to the `owner` Cachix cache and hosts pull the identical store path instead of compiling (used by llama-cpp, llama-cpp-cuda, karakeep).

### Restricted sudo + Askpass Pattern
The pi coding agent's `~/.local/bin/sudo` wrapper: NOPASSWD allowlist covers only `nixos-rebuild` and `systemctl <subcommand> *`; anything else goes through `sudo -A` with a zenity askpass (GUI dialog on the desktop, password only ever on an internal pipe). `timestamp_timeout=0` forces re-prompting. Headless hosts degrade to a clear error message instead of a password prompt.

### Power Management
`power-supply-handler` responds to battery level (<75% threshold) via udev rules + a periodic timer — disabling/enabling CPUs, starting/stopping services, adjusting GPU frequency, toggling peripherals, even removing the secondary NVMe when below threshold.

### Home-Manager sops-nix Pattern
Home-manager modules declare `sops.secrets` directly. A `home.activation` script then reads the decrypted secret path at activation time to write config files (e.g., `~/.pi/agent/auth.json`). This avoids putting secrets in the Nix store while keeping the activation declarative.
